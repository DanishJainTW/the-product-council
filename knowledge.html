The scout runs first, and alone

How the council fetches context before anyone else speaks.

  1. The orchestrator states which facts the decision needs
  2. context-scout runs by itself and returns a Context Pack with a coverage verdict
  3. The orchestrator gates it: sends a thin pack back once, and asks you about any conflict the decision depends on before a panel runs
  4. The orchestrator writes the panel brief from the pack, naming the gaps so no panel assumes them
  5. Panels run in parallel with each other, on that one brief
  6. Citations are checked, then the options and the recommendation are written

A panel briefed before the facts arrive fills the gap with a guess, and a guess with a citation attached is worse than silence. A conflict the gate finds goes into the intake questions, so you hear one set of questions, not two.

Context before questions

The council never asks you something it already knows. Before any question, the scout looks up everything your request names: features, personas, teams, systems, partners, districts, terms and figures, in the knowledge base, past sessions and analysis documents. For each intake topic it reports answered, partial or not in context.

What happens to a topic or question, by what the context holds.
Context saysWhat you see
AnsweredNot asked. Shown under "What I already know" with its source, so you can correct it
PartialA question for the missing piece only, quoting what is known
Not in contextA full question with a default

The panels' questions and figures go through the same check before reply 2. A figure the context holds is used, never requested. When your answer names something new, it is looked up before the next round.

New context from the chat

When you say something the knowledge base does not hold, the council asks once where it goes.

Where new context can go. Options 2 to 4 show a before and after and wait for your go, on your branch.
ChoiceWhere it goes
1. This analysis onlyThe session file and the analysis document. The knowledge base does not change
2. Key factA number, date, name or status, in the curated key facts
3. RuleA business, policy or compliance rule, in the curated topic file it belongs to
4. Background contextA process, pain point or driver, in the curated topic or theme file
